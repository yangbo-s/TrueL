# 语言与风格工作窗（0.5.0）

GOAL-079：让原文、译文的语言与操作位置一眼可辨，并让快捷浮窗在结束后回到普通工作窗。

| 需求 / 验收 | 行为 / 输入输出 | 实现与验证 |
| --- | --- | --- |
| REQ-079 / AC-079 | 仅 Ctrl+C+C、Ctrl+A+A 进入快速模式；外部点击或关闭结束临时会话，重开是双栏；保留原文和已完成结果 | AppDelegate 生命周期；关闭、失焦、设置、Dock 重开测试 |
| REQ-080 / AC-080 | 原文右上检测语言或手动选择；译文右上目标语言；已知相同语言自动使用另一目标 | LanguageOptions / DemoModel；中英、短文本、显式语言测试 |
| REQ-081 / AC-081 | 钉子左侧互换语言；有完整译文时将译文放到原文并反向翻译；快捷模式及改写禁用互换 | AppDelegate.swapLanguages；数据、选区、请求测试 |
| REQ-082 / AC-082 | 翻译与改写各自保存预设风格；选择新风格从原文重新生成；移除追加指令输入 | TextStyle / Preferences / LanguageEngine；请求契约与持久化测试 |
| REQ-083 / AC-083 | 复制在结果底部与风格相邻；替换在右下且常显回车；双栏标题、正文、底栏基线一致 | PopupView；明暗/最窄宽度/长文本截图与 native frame 检查 |
| REQ-084 / AC-084 | 改写保持原文语言，修改解释和用法提示保留；Return 工作窗提交、快捷结果替换 | 模型、Return policy 与原生按键回归 |
| REQ-085 / AC-085 | 源码、DMG、签名更新源发布并公开回读；固定凭据组件保持字节一致 | 发布及两次真实 Sparkle 更新验证 |

CON-079：SwiftUI/AppKit、同一 NSPanel；不动用户正在运行的应用和草稿，不使用真实 Key 做验收。保留 12 pt 控件、14 pt 正文、28 pt 控件高、12 pt 边距、8 pt 岛间距。无新依赖。

ASM-079：快速模式即使普通工作窗已置顶，也按临时会话点击外部收起。改写保持原文语言；互换仅在普通翻译取得完整结果、来源语言已知时可用。无法可靠检测的短文本继续显示“检测语言”，可手选。

ADR-079：沿用单窗口与原生菜单，把语言/风格建模为共享选项；不创建第二套快速界面，也不把语言识别交给另一次付费 API 请求。使用系统 NaturalLanguage 在本地检测。原文选择和偏好目标分开，实际目标避免同语言；同一汉语的简繁转换仍可选。

IF-079：LanguageRequest 输入 source 非空 UTF-8、mode、可选 sourceLanguage、targetLanguage、writingStyle；风格 ID 由目录校验，未知值回落 standard。翻译输出纯文本；改写输出 JSON output/corrections/tip；错误沿用现有内联错误与重试。参数改变取消旧请求，异步旧结果不得回填。风格不会改变 inputRevision；语言互换改变原文并作废外部替换绑定。

MOD-079：LanguageOptions 负责语言解析/回退与风格提示；DemoModel 负责源文本、请求版本及有效语言；Preferences 保存目标与两种风格；AppDelegate 管理窗口生命周期/互换/重生成；PopupView 复用原生菜单和按钮，不自行分派键盘。

OOS-079：新增服务商、Key 存储方式、全局快捷键录制算法及图标主题不在本轮范围。

实施：选项与模型 → 生命周期与布局 → 状态/语言/请求测试 → 实际截图、点击和关闭回归 → 发布验证。验收证据和 100 分制评分追加于发布记录。

REQ-086 / AC-086（追加）：所有语言、模型、风格和设置下拉框共用 SettingsMenuButton 渲染；文本左边与箭头右边的槽位边距均为 12 pt，箭头使用同一 SF Symbols chevron.down，保持原始宽高比。紧凑菜单按内容宽度，不留人为最小宽度。界面所有符号经 PopupGlyph 以 SF Symbols regular/monochrome 渲染，原生菜单箭头同库同字重；28 pt 点击区域不变。应用品牌图标六种选项保持不变。用控件几何、截断文本、明暗悬停截图验证。
