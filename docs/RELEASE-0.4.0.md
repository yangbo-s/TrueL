| 用例 / 需求 | 实际结果 |

| TC-071 / REQ-071 | Return 路由和按钮样式共用 PopupSession。快速结果 Return 替换；原生调整框的 Return 提交指令；空调整框不回落到替换。处理中不重复提交，编辑器保留 IME 和 Shift+Return。实际原生字段编辑器与只读结果视图的键盘路由测试通过。 |
| TC-072 / REQ-073 | 默认 Ctrl+C+C、Ctrl+A+A；只迁移旧默认值，保留自定义、禁用和冲突配置。配置前缀完成时触发一次；超时、失配、切换来源及暂停时归还暂存事件。原生 Command+C 序列仍保留复制行为。 |
| TC-073 / REQ-074 | 独立原生测试窗口中，Ctrl+A+A 保留原选区，结果窗口激活后仍准确替换；Ctrl+C+C 只触发一次。改变范围、关闭来源和只读文字均拒绝写入。未完成 Ctrl+A 超时后恢复行首动作；失配后先回放 Ctrl+A，再输入新字符，事件顺序正确。 |
| TC-074 / REQ-072、075 | 字号统一为 14 pt，行高 22 pt；左右滚动视口上下边缘、正文相对起点及滚动条相对边缘误差 ≤ 0.5 pt。736 / 960 pt、两种系统滚动条偏好、浅深色与顶部 / 中部 / 底部均检查。末行可完整滚入视口。 |

最终 Swift 测试为 **141 项 / 16 个 suite，通过**。4 项凭据打包检查、3 项发布检查、网格与差异检查通过。原生工作流探针的 6 项检查通过；它只操作本次创建的测试窗口，不读取真实 API Key 或修改用户文档。

最终构建共拍摄并审阅 **122 张实际窗口截图**：28 张快速 / 对照 / 焦点 / 加载 / 错误状态，62 张完整窗口与设置矩阵，32 张两类系统滚动条的对齐状态。截图使用模拟数据，生产 API 管线不变。检查脚本确认活动窗口、三个原生红绿灯、单窗口及滚动区数量；视觉审阅另外核对文字、边距和按钮状态。

截图审阅曾发现译文在调整框获得焦点时收窄成一列：SwiftUI 测量宽度时修改了正在显示的 NSTextContainer。改用独立文本容器测量、让显示容器跟随真实视口，重新构建和截图后正文宽度稳定。新增几何测试在旧实现也能通过，因此这项修复的直接证据是修复前后的实际截图，而不是声称单元测试复现了旧故障。另修正加载截图被模拟服务观察回调取消、错误截图丢失重试原文的问题，检查脚本现验证这些状态确实成立。

证据保存在本地 `artifacts/workflows-0.4.0/`：`screenshots`、`all`、`alignment`、`overlay` 为原始截图，`review` 为检视拼图，`before/focus-collapse-contact.png` 为焦点问题截图；`logs/tests.log` 与 `logs/native-workflows-final.log` 为最终测试日志。原始截图保留完整窗口。
