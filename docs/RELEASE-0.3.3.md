# 0.3.3 正文对齐验收

GOAL-067：让主浮窗的原文、译文和改写结果使用一致的正文字号，并使上下滚动条及文字起点对齐。

| 需求 / 验收 | 实现范围与约束 | 验证 |
| --- | --- | --- |
| REQ-067 / AC-067：三处正文均为 14 pt，原文与译文使用相同行高 | 复用 TypeScale；保留控件、标题和辅助说明的语义层级 | TC-067：实际渲染的 NSTextView 字体与段落属性；翻译、改写截图 |
| REQ-068 / AC-068：上下滚动容器左右边缘、正文起点一致 | 主浮窗两类结果；跟随系统滚动条显示偏好；长文本不遮挡 | TC-068：真实窗口坐标，常显 / 自动滚动条、默认 / 拉宽、浅 / 深外观 |
| REQ-069 / AC-069：保持原有编辑、结果操作和固定凭据组件，发布可更新的安装包 | 不修改真实 Key、API 请求或用户现有编辑内容；0.3.3 build 11 | TC-069：编辑与窗口回归、逐页截图、打包身份校验、公开安装包及 Sparkle 更新检查 |

输入是 UTF-8 原文及已有结果，包含空文本、中英混排、长段落、项目列表及改写高亮；输出仍为同一工作浮窗。无新接口、持久化或权限变化。错误与空状态沿用现有行为。

方案：原文和结果共用正文尺度；滚动容器在岛内保留 12 pt 外边距，正文再内缩 12 pt。修正现有 AppKit 编辑器和 SwiftUI 结果的边距，保留原生编辑、选择及滚动行为。无需替换渲染器或自绘滚动条。先记录旧版截图及失败的窗口坐标断言，再修正、截图复验、构建发布。

## 证据
